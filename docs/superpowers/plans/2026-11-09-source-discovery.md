# Поиск новых источников: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Цель:** раз в неделю находить новые публичные источники о маркетплейсах, показывать их владельцу в защищённой веб-панели и подключать к сбору только после проверки и одобрения.

**Архитектура:** отдельная команда `discover-sources` объединяет результаты Exa Search Lite и поисковых RSS Google News, группируя статьи в кандидатов-издателей. Кандидаты и решения хранятся в PostgreSQL; статические источники из JSON остаются начальными настройками, а одобренные источники из базы не перезаписываются при синхронизации. До одобрения адрес проверяется безопасным запросом; интерфейс действий доступен только через Basic Auth.

**Стек:** Python 3.12+, PostgreSQL, `urllib`/XML-парсер из стандартной библиотеки, существующий `unittest` и локальный HTTP-тестовый сервер.

**Спецификация:** `SPEC.md`, задача 3 — «Поиск и проверка новых источников».

## Общие ограничения

- Автоматический поиск запускается отдельно от `cycle` и планируется раз в неделю; ручной запуск остаётся доступным.
- Exa вызывается только с `EXA_API_KEY`, в режиме Lite, с категорией `news` и максимум 10 результатами на запрос; владелец заранее выключает платные перерасходы в аккаунте Exa.
- При исчерпании кредитов/лимита или сигнале оплаты Exa приостанавливается до следующего месяца UTC; Google News RSS продолжает работать. Приложение не покупает и не пополняет кредиты.
- Новый источник не включается в сбор до одобрения владельцем. Кандидаты и поисковые статьи не попадают в обычную новостную ленту.
- Допускаются только публичные источники и типы `rss`, `html`, `telegram`; не обходить авторизацию, CAPTCHA или ограничения доступа.
- Внешние запросы к адресам кандидатов требуют HTTPS, проверки DNS/IP и перенаправлений, ограничения времени и размера ответа.
- Ключи и токены не включать в код, тесты, артефакты или коммиты.
- Задача 3 фиксируется одним коммитом с номером `3`; перед ним запускается весь набор тестов с отдельной PostgreSQL.

## Области риска для проверки

- Результат RSS поисковика — статья или агрегатор, а не источник: хранить её только как пример, группировать по издателю и отдельно проверять адрес сбора.
- Домены-кандидаты могут содержать дубли или совпадать с активными источниками: нормализовать домен и URL до вставки.
- Публичный URL может перенаправить на loopback/private/link-local/reserved IP или разрешаться в такой IP: проверять и закреплять публичный адрес при соединении и проверять каждый redirect.
- `sources.json` синхронизируется при запуске коллектора и веб-сервера: синхронизация не должна менять одобренные вручную записи.
- Exa может исчерпать бесплатный баланс или вернуть ошибку, а Google RSS — временно не отвечать: каждый канал изолирован, ошибка одного не отменяет результат второго.
- Действие одобрения — запись состояния: Telegram-сессия недостаточна; требуются Basic Auth, same-origin защита, строгая схема запроса и успешная проба источника.

### Задача 1: Поисковые провайдеры и единый формат результатов

**Файлы:**
- Создать: `source_discovery/__init__.py` — пакет поиска.
- Создать: `source_discovery/providers.py` — Exa, Google News RSS, разбор и нормализация поисковых результатов.
- Создать: `source_discovery/queries.py` — фиксированные русские запросы по Ozon, Wildberries, Яндекс Маркету и маркировке «Честный знак».
- Создать: `tests/test_source_discovery.py` — локальные ответы провайдеров и разбор XML.

**Интерфейсы:**
- `source_discovery/__init__.py` defines `SearchHit`, `SearchBatch` and `SourceCandidate` typed structures shared by providers, grouping, and storage.
- `parse_google_news_rss(data: bytes) -> list[SearchHit]` возвращает заголовок, URL статьи, дату и издателя из RSS.
- `search_exa(query: str, api_key: str, *, open_url=open_url) -> list[SearchHit]` вызывает только фиксированный `https://api.exa.ai/search`, режим `lite`, категорию `news`, до 10 результатов; URL результата считается примером публикации.
- `search_all(*, api_key: str | None, queries: list[str]) -> SearchBatch` изолирует ошибки каждого провайдера и возвращает успешные результаты вместе с безопасными статусами ошибок.
- `SearchHit` содержит `title`, `article_url`, `published_at`, `publisher`, `publisher_url` и `provider`; для Exa `publisher_url` вычисляется из hostname результата, для Google берётся из RSS `<source url>`; секреты и необработанные ответы API в структуру не входят.
- `group_candidates(hits: list[SearchHit]) -> list[SourceCandidate]` группирует по домену издателя, исключает `news.google.com`, сохраняет URL публикаций как примеры и предлагает `publisher_url`; для Exa без него использует только корень origin результата, никогда URL статьи.

### Задача 2: Очередь кандидатов и сохранение решений

**Файлы:**

**Интерфейсы:**
- `db.upsert_source_candidates(conn, candidates: list[dict]) -> int` сохраняет структуры `SourceCandidate` по нормализованному домену и collection URL, обновляя примеры без дубликатов.
- `db.list_source_candidates(conn, status: str = "pending") -> list[dict]` возвращает ограниченный список с полями карточки.
- `db.pause_exa_until(conn, until: datetime, reason: str) -> None` и `db.exa_pause_until(conn) -> datetime | None` сохраняют паузу при подтверждённом исчерпании кредита/оплате.

- `sources.managed_by` различает строки начального JSON и одобренные вручную источники; синхронизация JSON обновляет только JSON-источники.

### Задача 3: Безопасная проверка адресов и одобрение источника

**Файлы:**
- Создать: `source_discovery/probe.py` — обнаружение поддерживаемого collection URL и пробный разбор.
- Создать: `collector/safe_fetch.py` — безопасная загрузка публичных HTTPS URL с контролем DNS, перенаправлений, времени и размера.
- Изменить: `collector/main.py` — использовать безопасный загрузчик для активных URL и не собирать неподдерживаемые источники.
- Изменить: `db/__init__.py` — атомарное одобрение/отклонение после успешной пробы.
- Создать: `tests/test_safe_fetch.py` и дополнить `tests/test_source_candidates.py`.

**Интерфейсы:**
- `safe_fetch.fetch_public(url: str, *, timeout: float = 10, max_bytes: int = 2_000_000, opener=...) -> bytes` принимает только HTTPS, проверяет hostname и закреплённый публичный IP, отключает автоматические redirects и сам проверяет каждый redirect.
- `probe_source(url: str) -> ProbeResult` проверяет предложенную публичную страницу, ищет RSS/Atom auto-discovery и валидирует feed, принимает прямой Telegram preview либо явно заданный владельцем HTML snapshot; URL статьи или невалидный feed не проходит.
- `db.review_source_candidate(conn, candidate_id: int, action: str, fields: dict, probe: dict)` допускает `approve|reject`; `approve` без успешной пробы отклоняется, а запись источника и статус кандидата изменяются атомарно. Только сервер вызывает `probe_source`; клиент не может прислать готовый результат пробы.
- Код одобренного источника стабилен: `discovered_` + первые 24 hex-символа SHA-256 от `publisher_domain + "|" + collection_url`; category/trust ограничены действующими значениями.
