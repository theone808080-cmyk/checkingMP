# Полезная лента маркетплейсов — план реализации

> **Для исполнителя:** выполнять план по шагам, сверяясь со SPEC и тестами; независимый автор тестов не меняет рабочий код, а отдельный агент запускает проверки.

**Цель:** сделать ленту находок Mini App отсортированной по пользе для продавца, компактной и прозрачной в показе классификации и проверок.

**Архитектура:** расширить серверную выборку `db.feed_findings` полями классификатора и последнего фактического аудита, добавить сортировку по категории полезности и серверные фильтры для дополнительных параметров. В `web/miniapp.html` оставить период и площадку на виду, остальные фильтры сгруппировать и показать компактные метки статусов на карточках. Схему данных и процесс обработки не менять.

**Стек:** Python 3.12, PostgreSQL, встроенный HTTP-сервер, HTML/CSS/JavaScript Mini App, unittest и Node UI harness.

**SPEC:** [spec.md](spec.md)

## Ограничения

- Одна проектная задача — один коммит: `feat(15): prioritize useful marketplace feed`.
- Тесты пишет независимый агент; исходные тесты подтверждает RED отдельный агент; полный набор запускает другой независимый агент до коммита.
- Не включать классификатор в production-фильтр по умолчанию, не менять сбор/перевод/генерацию и не создавать результаты аудита.
- Сохранять имеющиеся контракты, тему Telegram, авторизацию, снимки пагинации и стабильный курсор. Для новых фильтров включить их значения в отпечаток курсора.
- В Git не добавлять ключи, токены, реальные данные и локальные результаты проверки.

## Область изменений

| Файл | Ответственность |
|---|---|
| `db/__init__.py` | Валидация фильтров, выборка, агрегирование оценок классификатора и последнего статуса аудита, usefulness ordering, снимки и курсор |
| `web/main.py` | Разбор разрешённых параметров API и передача фильтров в базу, включая endpoint счётчиков |
| `web/miniapp.html` | Плотность и иерархия ленты, группа дополнительных фильтров, метки статусов и раскрываемые детали |
| `tests/test_findings.py`, `tests/test_web_api.py` | Контракты БД/API-выборки, сортировка, статусы, фильтры, счётчики и курсоры |
| `tests/miniapp_findings_test.js` | Доступность фильтров и карточек, отдельные статусы судей и состояния отсутствующих записей |
| `README.md`, `kanban.md`, `progress.md` | Навигация и фиксация только проверенного результата задачи |

## Шаги

### Задача 15 — полезная и читаемая лента

1. **Тесты (отдельный автор):** расширить `tests/test_findings.py`. Проверить usefulness ordering для `practical_change`, `seller_action_or_risk`, `industry_context`, `uncertain` и отсутствующей классификации; tie-break по importance, свежести, ID; агрегацию нескольких материалов по версии правил; вывод последнего фактического результата аудита отдельно по `summary`/`recommendation`; фильтры воздействия и аудита; согласованность счётчиков, снимков и курсора. Проверить отклонение недопустимых значений.
2. **API-контракты (отдельный автор):** расширить `tests/test_web_api.py`: проверить приём и передачу новых фильтров для выдачи и счётчиков, отклонение неверных статусов.
3. **Тесты интерфейса (отдельный автор):** расширить `tests/miniapp_findings_test.js`. Проверить, что видимые фильтры — период и площадка, дополнительные фильтры раскрываются; карточка показывает классификацию, влияние, verification, два статуса аудита; пустые данные отображают «нет оценки»/«не проверено», не «проверено»; смена фильтра перезапрашивает выдачу и сбрасывает курсор.
4. **Подтверждение RED:** отдельный агент запускает новые целевые тесты на исходном коде. Переходить к production-изменениям после фиксации ожидаемых падений.
5. **Данные и сортировка:** расширить `db.feed_findings` без изменения схемы БД. Для каждой находки агрегировать существующие оценки активной версии правил по связанным материалам; вывести отсутствие оценки явно. Получать последнее сохранённое качество отдельно для сводки и рекомендации. Расположить записи по категории полезности, importance DESC, updated_at DESC, id DESC. Расширить фильтр-хэш, курсор, SQL, счётчики и API для влияния продавцу и статусов аудита; не менять глобальную настройку фильтра релевантности.
6. **API:** обновить `web/main.py`: принять и проверить новые параметры в `/api/findings` и `/api/findings/counts`; передать одинаковый набор фильтров для обеих операций; сохранить запрет неизвестных параметров и поднять лимит числа query-параметров ровно настолько, чтобы все разрешённые фильтры и курсор могли передаваться вместе.
7. **Интерфейс:** обновить `web/miniapp.html` — компактные базовые элементы, дополнительные фильтры под раскрытием, активные метки, лаконичные карточки. Показывать статусы классификатора, проверки находки и два результата аудита раздельно. Явно обозначить отсутствующие записи без ложного «ОК». Сохранить доступность клавиатуры, адаптивность, состояния загрузки/ошибки/пустого результата и стили Telegram.
8. **Локальные проверки:** после RED отдельный test runner (не автор кода и не автор тестов) запускает целевые тесты БД/API и UI harness. Автор кода проверяет синтаксис и `git diff --check`; UI detector запускается один раз после изменений интерфейса.
9. **Полный набор:** отдельный агент, не автор кода и не автор тестов, запускает все тесты по инструкции README с изолированной PostgreSQL 17. Docker smoke-тесты отмечаются пропущенными только при подтверждённом отсутствии Docker CLI.
10. **Сверка и коммит:** проверить каждый критерий SPEC, отсутствие секретов и незапрошенных файлов; обновить навигацию README, статус Kanban и progress только фактическим результатом; один коммит с номером `15`.

## Фокус итогового обзора

- Категория сортировки рассчитывается только из сохранённых полей классификатора; отсутствие оценки не превращается в положительную классификацию.
- Несколько связанных материалов не размножают находку и не превращают разногласие в безусловное подтверждение.
- Статусы качества берутся по последней реально сохранённой записи раздельно для сводки и рекомендации; отсутствующая запись не отображается как `ok`.
- WHERE-параметры списка и счётчика согласованы; фильтры входят в cursor fingerprint и snapshot порядка.
- Изменение не включает фильтр релевантности и не скрывает неопределённые/неоценённые материалы.
- Mini App остаётся читаемым на мобильной ширине и не теряет доступность.
