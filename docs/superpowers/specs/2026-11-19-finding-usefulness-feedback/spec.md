# Спецификация: оценка полезности ИИ-находок

**Статус:** утверждена владельцем 2026-11-19.
**Номер задачи:** 25.

## Цель

Дать владельцу радара возможность отмечать, помогает ли конкретная находка следить за рынком. Эти оценки помогут позднее оценивать качество отбора; сами по себе они не меняют модель, порядок ленты или статус достоверности события.

## Подходы

1. **Две кнопки в карточке Mini App с сохранением последней оценки — выбранный вариант.** Владелец выбирает «Полезно» или «Не подходит»; отметка привязана к находке и остаётся после повторного открытия. Это соответствует текущему сценарию просмотра находок.
2. Отправлять реакции эмодзи в Telegram рядом с уведомлениями. Не подходит для оценки всех карточек: владелец открывает ленту независимо от уведомлений, а реакции сложно связать с историей карточек.
3. Выгружать отдельную таблицу для ручной разметки. Подходит для исследовательской выборки, но не даёт быстро оценивать новости при обычном чтении.

## Поведение

- В каждой карточке находки показывать действия «Полезно» и «Не подходит».
- Сохранять одну текущую оценку владельца на одну находку. Повторный выбор меняет предыдущую отметку; выбранное состояние отображается после загрузки карточки.
- Сохранение доступно только через существующую авторизацию Telegram Mini App/веб-панели. Оценка сохраняется на сервере в PostgreSQL.
- Ошибку сохранения показывать владельцу и не выдавать несохранённую отметку за сохранённую.
- Оценка полезности не подтверждает достоверность находки: поле «Подтверждено / Нужно проверить» остаётся отдельным.

## Границы

- Не менять сбор новостей, промпт модели, классификацию релевантности, сортировку, фильтры и статус проверки находки.
- Не отправлять оценки модели автоматически и не менять её поведение на их основании.
- Не добавлять комментарии, причины оценки, новые роли или аналитику в интерфейс.
- Не выполнять развёртывание; подготовить ветку и отправить её в GitHub для последующего деплоя владельцем.

## Критерии приёмки

1. В карточке можно выбрать одну из двух оценок, и выбранное состояние отображается после обновления ленты.
2. Оценку можно изменить; в базе хранится последняя оценка для каждой находки.
3. Ошибка API не показывает оценку как сохранённую; повторная попытка возможна.
4. Изменение оценки не меняет статус достоверности находки.
5. Только авторизованный владелец может читать и изменять оценки; неизвестная находка и недопустимое значение отклоняются.
6. Проверки покрывают хранение, авторизацию и отображение двух состояний.
7. Подготовлена сборка и отдельная ветка отправлена в GitHub; production не затрагивается.

## Решения реализации

- Реализовать поверх уже существующей ленты задачи 15 «Полезная лента новостей маркетплейсов».
- Использовать существующий механизм схемы БД и защищённый same-origin POST API Mini App.
- Не включать предыдущие незакоммиченные изменения основной рабочей копии в эту ветку.
