# Локальный worker через LM Studio

## Цель

Добавить к локальному радару ручной запуск обработки новых материалов моделью, доступной через LM Studio на ноутбуке. Облачный запуск и Railway в этот этап не входят.

## Поток данных

```text
публичные источники
  -> collector
  -> PostgreSQL: materials (status = new)
  -> local worker через LM Studio
  -> PostgreSQL: events + event_materials
  -> локальная web-страница
```

## Команды

- `collect` собирает материалы из активных публичных источников.
- `process` выбирает новую ограниченную партию, отправляет её в локальный OpenAI-совместимый HTTP API LM Studio и импортирует проверенные ответы в базу.
- `web` показывает сохранённые сигналы.
- `health` дополнительно показывает, доступен ли LM Studio, без запуска модели.

Все команды запускаются пользователем вручную. При выключенном ноутбуке сбор и обработка не выполняются.

## Граница worker

Worker получает только данные очереди `materials` и возвращает JSON со списком сигналов и пропущенных материалов. Для каждого сигнала обязательны: платформа, тема, важность, краткий вывод, рекомендуемое действие, статус проверки и ссылки на материалы. Ответ проверяется до записи в PostgreSQL. Некорректный ответ или недоступный LM Studio не меняет статусы материалов и даёт понятную ошибку.

## Настройка

В `.env.example` будут добавлены необязательные настройки адреса LM Studio, имени загруженной модели, тайм-аута и размера партии. По умолчанию используется локальный адрес LM Studio; секреты и ключи не требуются.

## Проверка

Тесты покроют формирование запроса к модели, разбор валидного и невалидного ответа, сохранение событий и поведение при недоступном сервере. Отдельно будет выполнена проверка `health`, тестовый запуск worker только при доступной локальной модели и HTTP-проверка веб-страницы.

## Не входит в этап

- Railway и другое облачное размещение;
- платные внешние API;
- запуск по расписанию;
- действия в кабинетах маркетплейсов;
- автоматическое признание сигнала юридически подтверждённым.
