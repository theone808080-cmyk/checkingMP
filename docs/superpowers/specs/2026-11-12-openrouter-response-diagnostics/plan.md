# Диагностика невалидного ответа OpenRouter — план реализации

> **Для исполнителя:** выполнять задачу по шагам в порядке RED → GREEN. Задача 11 составляет один коммит.

**Цель:** выявлять в серверном журнале безопасную причину отказа проверки ответа OpenRouter, не раскрывая секреты и содержимое материалов.

**Архитектура:** `worker.infer` будет присваивать фиксированные коды этапа и причины на границах разбора конверта, извлечения текста, разбора JSON содержимого и проверки схемы. При отказе функция запишет в stderr строку `openrouter_diagnostic ` и JSON-объект с разрешёнными полями и ASCII-экранированием, чтобы Unicode-разделители не ломали одну физическую строку; существующее исключение и неизменность очереди сохраняются.

**Технологии:** Python 3.12, стандартный `json`/`logging` или stdout-печать JSON, `unittest`; существующий рабочий клиент OpenRouter.

**Спецификация:** `docs/superpowers/specs/2026-11-12-openrouter-response-diagnostics/spec.md`.

## Общие ограничения

- Не записывать ключи, заголовки авторизации, промпты, исходные материалы, полный ответ, тело HTTP-ошибки или произвольный текст исключений.
- Не менять успешный формат ответа, схему проверки, очередь, число запросов или поведение повторов.
- При невалидном ответе материалы остаются в очереди необработанными.
- Тесты пишет отдельный от автора кода агент; полный набор запускает третий агент.
- Перед коммитом запускать полный набор; один коммит с номером задачи `11`.

## Файлы и ответственность

- `worker/main.py` — фиксированные категории диагностики, безопасная запись события и передача доступного `cycle_id` в `infer`.
- `tests/test_worker.py` — проверки категорий, безопасных полей и сохранения существующего отказа.
- `README.md`, `kanban.md`, SPEC/plan/tasks в папке задачи — проектная навигация и синхронизация SDD-статуса.

## Review focus

- Невалидный UTF-8/JSON конверта не должен попасть в журнал сырой строкой.
- Отсутствующая структура `choices/message/content` должна отличаться от некорректного JSON.
- Некорректный JSON содержимого должен иметь отдельную причину от ошибки конверта.
- Нарушения схемы и ID должны журналироваться фиксированным кодом, без значений ответа.
- При исключении, содержащем контрольные секреты или текст материалов, эти значения не должны появляться в stdout/stderr; очередь не должна импортироваться.

**Интерфейс:** `infer(batch, *, cycle_id=None)` сохраняет прежний результат и исключения верхнего уровня. При некорректном ответе пишет JSON-объект со строго ограниченными полями: `event="openrouter_response_rejected"`, `stage` (`envelope`, `content`, `schema`), `reason`, `cycle_id` (если задан), `model`, `batch_size`, `http_status` (если получен). Коды причин фиксированы: `invalid_envelope_json`, `invalid_envelope_shape`, `missing_content`, `content_not_text`, `invalid_completion_json`, `schema_required_fields`, `schema_signal_fields`, `schema_importance`, `schema_material_ids`, `schema_translation`. Не включать текст исключения и модельные значения. `process` передаёт цикл.
