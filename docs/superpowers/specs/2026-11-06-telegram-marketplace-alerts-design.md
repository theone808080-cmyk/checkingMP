# Уведомления МП-радара в Telegram: проектное решение

## Цель

После каждого серверного цикла радар должен присылать Ивану Усенкову в личный чат с существующим ботом `@Findersmpbot` все новые модельные сигналы уровней `info`, `important` и `critical`. Старая AI-рассылка Finder должна быть отключена отдельной операцией после определения её текущего места запуска.

## Границы

В этой доработке не меняются источники, правила отбора материалов, OpenRouter, веб-страница и расписание `cycle`. Радар не выполняет действий в кабинетах маркетплейсов и не принимает команд от Telegram-пользователей. Сигналы остаются черновиками с признаком `needs_check`, а сообщение содержит это ограничение.

Токен существующего бота и идентификатор личного чата не хранятся в Git, тестовых данных, логах или документации. Они задаются только переменными окружения Coolify: `TELEGRAM_TOKEN` и `TELEGRAM_CHAT_ID`.

## Поток данных

1. `python main.py cycle` собирает материалы и обрабатывает ограниченную очередь через OpenRouter, как работает сейчас.
2. После успешной обработки сервис выбирает из PostgreSQL ещё не доставленные сигналы всех трёх уровней: `info`, `important` и `critical`.
3. Для каждого сигнала Telegram-модуль отправляет краткое сообщение в единственный разрешённый `TELEGRAM_CHAT_ID`: важность, площадка, что изменилось, что сделать и ссылку на источник.
4. Только после подтверждённого ответа Telegram API запись получает отметку о доставке. Повторный цикл её не отправляет.
5. При сетевой ошибке Telegram отметка не ставится. Такой сигнал останется доступным для попытки в следующем цикле; при этом сбор, обработка и веб-страница не считаются неуспешными из-за канала уведомлений.

## Данные и защита от дублей

Для сигналов добавляются поля времени доставки Telegram и последней ошибки доставки. Выборка выполняется с блокировкой строк в транзакции, чтобы два параллельных запуска не отправили один сигнал дважды. Отметка о доставке выставляется только при HTTP-ответе Telegram API с `ok: true`. Если сеть оборвётся после того, как Telegram уже принял сообщение, но до ответа приложению, ни Telegram Bot API, ни PostgreSQL не позволяют надёжно отличить доставку от недоставки: следующая попытка может создать редкий дубль. Это ограничение фиксируется в диагностике, а не маскируется обещанием абсолютной идемпотентности.

Для каждого из трёх уровней сообщение создаётся из уже сохранённых полей, не добавляет новых выводов модели и явно указывает, что это сигнал для проверки, а не юридическое заключение. Настройка пользовательского фильтра по важности не входит в первую версию и будет добавлена отдельным изменением после накопления реальных уведомлений.

## Отказоустойчивость

Отсутствующие или некорректные `TELEGRAM_TOKEN` и `TELEGRAM_CHAT_ID` не должны приводить к отправке куда-либо по умолчанию. В таком случае цикл завершает сбор и обработку как обычно, а модуль уведомлений записывает понятную диагностическую ошибку без раскрытия токена.

Сетевые ошибки Telegram не вызывают повторную отправку в том же запуске: это уменьшает риск дублей и неконтролируемых повторов. Следующий запланированный цикл попробует ещё раз. Токен не выводится ни в исключениях, ни в HTTP-логах.

## Отключение старой AI-рассылки

Скриншот подтверждает, что AI-подборку в 09:00 прислал `@Findersmpbot`; место её запуска в текущих локальных файлах не найдено. Отключение старой задачи — отдельная управляемая операция на сервере Finder: сначала определяется точный планировщик и команда, затем пользователь подтверждает отключение. До этого новая функция радара не может гарантировать прекращение старой AI-рассылки.

## Проверка

Автоматические тесты должны покрыть: отбор всех трёх уровней важности; форматирование сообщения; отсутствие HTTP-вызова при пустой выборке или отсутствующей конфигурации; установку отметки только после ответа Telegram `ok: true`; сохранение неотправленного сигнала при ошибке; отсутствие дубля при повторном запуске.

После развёртывания пользователь вручную задаёт две секретные переменные в Coolify. Затем выполняется одна контролируемая отправка в личный чат, проверяется содержание и повторный запуск без дублирования. Только после этого настраивается или подтверждается плановое выполнение.
