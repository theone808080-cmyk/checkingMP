# Карточки влияния новостей на склад — план реализации

> **Для исполнителей:** выполнять план через subagent-driven development или executing-plans по одной задаче за раз. Каждый шаг имеет проверяемый результат.

**Цель:** дать владельцу возможность видеть и подтверждать связь новости с площадкой/СЦ и процессами склада.

**Архитектура:** формировать черновик из полей уже сохранённой находки и связанного источника без дополнительного вызова модели; сохранять одну или несколько отдельных карточек влияния на находку, не меняя саму находку. Показывать карточки в подробностях Mini App. Записи создаются как неподтверждённые; владелец подтверждает, отклоняет или исправляет их через авторизованную сессию Telegram.

**Стек:** Python 3.12, PostgreSQL, существующий HTTP-сервер и Telegram Mini App, JavaScript, `unittest`.

**Спецификация:** `docs/superpowers/specs/2026-11-16-warehouse-news-impact/spec.md`.

## Общие ограничения

- Не подключать WMS, кабинеты маркетплейсов или новые внешние сервисы.
- Не вычислять денежный эффект и не выдумывать отсутствующие даты/тарифы.
- Не добавлять вызов модели: использовать только `platform`, `topic`, `effective_date`, `summary`, `recommended_action` и связанные URL; точное имя СЦ/процесса не заполнять, если оно отсутствует.
- Автоматические предложения всегда начинаются со статуса `needs_review`.
- Подтверждение владельца относится только к связи новости с объектом/процессом.
- Не менять находку, её проверку, важность, ленту и расписание.
- Сохранить Telegram session authorization и same-origin защиту для запросов изменения.
- Изменения должны быть обратно совместимыми с существующей PostgreSQL.

## Обзор файлов

- `db/schema.sql`: отдельная таблица `finding_impacts`, индексы и ограничения.
- `db/impacts.py`: выборка, создание, правка и решение по карточкам.
- `db/__init__.py`: публичные обёртки по существующему стилю.
- `web/main.py`: API авторизованной сессии для чтения/сохранения карточек.
- `web/miniapp.html`: локальный неподтверждённый черновик для тем тарифов и складской логистики, включая доставку, поставки, отгрузку, приёмку и возвраты; отображение сохранённых карточек и формы подтверждения/правки.
- `tests/test_finding_impacts.py`, `tests/miniapp_findings_test.js`, `tests/test_web_api.py`: отдельный тестовый агент добавляет тесты; независимый агент выполняет обязательный прогон.
- `README.md`, `kanban.md`, `progress.md`: навигация и статус по правилам проекта.

## Review focus

- Одна находка с несколькими СЦ/процессами сохраняет все карточки без перезаписи.
- Черновик из текущей находки не инициирует дополнительный OpenRouter-запрос.
- Неизвестный СЦ/процесс показывается как неуказанный и не угадывается по названию площадки.
- Дата/тариф отсутствуют в источнике: UI показывает «не указано», а не генерирует значение.
- Поддельный, истёкший или отсутствующий Telegram session cookie не может изменить карточку.
- Невалидный статус, пустой объект, избыточный текст или неизвестные поля отклоняются без частичной записи.
- Подтверждение карточки не меняет статус проверки исходной находки и не создаёт WMS-действие.
