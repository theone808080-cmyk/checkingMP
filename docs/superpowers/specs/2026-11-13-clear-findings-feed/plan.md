# Читаемая и надёжная лента находок — план реализации

> **Для исполнителя:** выполнять план по шагам, сверяясь с утверждённым SPEC и независимыми тестами.

**Цель:** упростить карточки находок, исключить принятие английского результата ИИ за перевод и объединять только точные копии публикаций.

**Архитектура:** технические статусы останутся в API, но Mini App покажет их в раскрываемом блоке «Проверки» и вынесет только сохранённые замечания в короткий маркер. Worker будет валидировать русскоязычность новых переводов, сводок и рекомендаций до импорта. PostgreSQL сохранит исходные материалы раздельно; индекс точного нормализованного содержимого позволит при импорте связать точную копию с уже существующей находкой и показать все источники.

**Стек:** Python 3.12, PostgreSQL, встроенный HTTP-сервер, HTML/CSS/JavaScript Mini App, unittest и Node UI harness.

**SPEC:** [spec.md](spec.md)

## Глобальные ограничения

- Одна задача проекта — один коммит с номером `16`.
- Независимый агент пишет тесты; другой независимый агент запускает полный набор до коммита.
- Переводить и проверять язык только новых материалов; `legacy`-материалы не переписывать.
- Не объединять публикации на основании семантического сходства; сравнивать нормализованные заголовок и текст без нечёткого/ИИ-сопоставления.
- Не удалять исходные материалы и сохранять для находки ссылки на все точные копии.
- Не менять сортировку, важность, сбор источников, расписание, фильтры, уведомления, авторизацию или результаты аудита.
- Не включать ключи, токены и реальные пользовательские данные в Git.
- Push, слияние и развёртывание не входят в задачу.

## Задача 16 — точность и читаемость находок

**Интерфейсы:** `worker.validate(payload, batch)` отклоняет не-русские новые переводы/сводки/рекомендации; `db.add_material(...)` хранит отдельный оригинал и его нормализованный отпечаток; `db.import_signals(...)` связывает новую точную копию с единственной уже существующей находкой, если такое соответствие однозначно; `web/miniapp.html` показывает статусы в блоке «Проверки».

1. **Тесты (независимый автор):** дополнить тесты Worker, БД и UI. Проверить английский ответ модели, допустимый русский текст с латинскими названиями брендов, неуспешную транзакцию при плохом языке, совпадение после нормализации пробелов, сохранение обеих записей/источников, отдельную выдачу похожих и неоднозначных публикаций и раскрываемый блок статусов без `needs_check` как ошибки. Защитный тест на неоднозначные совпадения уже проходит на базовой версии, потому что прежний код не выполняет дедупликацию; он остаётся страховкой для новой логики.
2. **RED:** другой агент запускает новые целевые проверки на исходном коде и фиксирует ожидаемые падения. Production-код до этого шага не меняется.
3. **Язык:** добавить один общий предикат русскоязычности для текстовых полей ИИ. Требовать, чтобы кириллические буквы составляли не менее половины всех буквенных символов; цифры, пунктуация и латинские названия при этом допустимы. Применять к каждому новому заголовку и любому непустому `text_ru`, а также к `summary`/`recommended_action` каждого сигнала. Любое нарушение отклоняет весь ответ до `import_signals`, не позволяя показать английский текст как перевод.
4. **Точный повтор:** добавить необязательный индексированный отпечаток заголовка и непустого текста после нормализации Unicode и свёртки пробелов, не меняя уникальный отпечаток исходной записи. Заполнять индекс существующих материалов однократно при инициализации схемы. При импорте объединять сигнал с существующей находкой лишь если совпадение точное и отпечаток ведёт ровно к одной существующей находке; при нескольких совпадениях оставить новую находку отдельной. Совпадение `event_key` само по себе не объединяет публикации: при конфликте ключа для не-дубля создать отдельное событие с детерминированным ключом из отпечатков исходных материалов и текста сигнала. Для ручного импорта подтверждение применяется к найденной копии только при совпадении уже проверенных полей события; отличающийся вручную текст сохраняется отдельной находкой. Все оригиналы, URL и источники остаются связаны с находкой; в раскрытых деталях показать число связанных источников.
5. **Карточка:** оставить API-поля статусов без изменений. Перенести пять описаний из основного заголовка карточки в нативный `<details>` с заголовком «Проверки». Снаружи показывать маркер только при сохранённом `review` или `issue`; не помечать отсутствие оценок или `needs_check` замечанием.
6. **Локальная проверка автором:** выполнить целевые тесты Worker, БД и UI; проверить синтаксис модулей и `git diff --check`; не переходить к коммиту, если любая проверка красная.
7. **Полная проверка (отдельный агент):** независимый от автора кода и тестов агент запускает полный набор по README на отдельной PostgreSQL 17; Docker smoke-тесты могут быть пропущены только при подтверждённом отсутствии Docker CLI.
8. **Сверка и коммит:** по критериям SPEC проверить отсутствие ложного объединения, потери источников и английского fallback; обновить README, Kanban и progress фактическим результатом; создать ровно один коммит `feat(16): clarify findings feed`.

## Фокус итогового обзора

- Коллизия нормализованного отпечатка не связывает материалы с несколькими существующими находками.
- Одна русская служебная фраза не делает в основном английскую сводку допустимой.
- Существующий результат аудита остаётся точным и не превращается в новое решение.
- Источники и исходные тексты точных дублей остаются доступными после объединения карточек.
- При невалидном языке очередь остаётся неизменной и не показывает исходный английский текст как готовый перевод.
