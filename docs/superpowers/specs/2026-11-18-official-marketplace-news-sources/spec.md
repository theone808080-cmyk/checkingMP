# SPEC: получение уведомлений продавца через Ozon Seller API

**Статус:** утверждена владельцем 2026-11-18 выбором «Подключить Seller API».
**Номер задачи:** 23.

## Цель

Добавить официальный Ozon Seller API как источник персональных уведомлений и новостей продавца, чтобы существующий конвейер мог выделять изменения, важные для комиссий, выплат, логистики и работы склада.

## Пользователь и сценарий

Владелец задаёт Client ID и API-ключ Ozon в защищённых переменных окружения Coolify. При обычном цикле сбора приложение получает список чатов типа `SELLER_API_NOTIFICATIONS`, читает новые сообщения и сохраняет их как материалы с датой и ссылкой на доступный первоисточник. Новые материалы обрабатываются существующей моделью и отображаются в текущей ленте.

## Текущее устройство и ограничения доступа

- В `config/sources.json` уже есть официальный Telegram-источник Ozon; новый API-источник дополняет его личными уведомлениями продавца.
- Официальная инструкция Ozon предлагает получить чаты через `/v3/chat/list`, отобрать `SELLER_API_NOTIFICATIONS` и читать сообщения через `/v3/chat/history`.
- Ozon указывает, что список чатов работает без Premium. История чатов по опубликованным условиям может требовать Premium Plus или Premium Pro. Владелец сообщил, что такой подписки нет, но Seller API доступен для некоторых запросов; успешное чтение истории заранее не подтверждено.
- При отсутствии ключей или отказе метода истории источник пропускается/фиксирует безопасную ошибку; остальные источники продолжают сбор. Секреты и содержимое сообщений не попадают в журналы.

## Предлагаемое поведение

1. Подключить только тип чата `SELLER_API_NOTIFICATIONS`; не включать `SELLER_API_UPDATES`, которые относятся к техническим изменениям API и могут добавлять шум.
2. Использовать только read-only методы `POST /v3/chat/list` и `POST /v3/chat/history` на `https://api-seller.ozon.ru`.
3. Читать `OZON_SELLER_CLIENT_ID` и `OZON_SELLER_API_KEY` из окружения. Не добавлять реальные значения в `.env.example`, Git, тесты или логи.
4. Запрашивать данные по существующему расписанию цикла; Push API не включать и не регистрировать webhook.
5. Преобразовывать новое сообщение в обычный материал с устойчивым идентификатором сообщения, текстом, временем публикации и URL из содержимого, если он есть. При отсутствии ссылки использовать официальный адрес кабинета Ozon и сохранять идентификатор сообщения для дедупликации.
6. Пропускать уже обработанные сообщения; передавать новые в существующий перевод, отбор, модель и ленту без дополнительного LLM-вызова на получение API-ответа.
7. Не отмечать сообщения прочитанными, не отправлять сообщения, не менять настройки кабинета и не выполнять другие операции API.

## Критерии приёмки

1. Источник выбирает только чаты `SELLER_API_NOTIFICATIONS` и не читает `SELLER_API_UPDATES`.
2. Каждый ответ сообщения нормализуется в отдельный материал с текстом, временем и устойчивым ID; повторный цикл не создаёт дубль.
3. API-ошибка авторизации, недоступности подписки или неверной структуры ответа не останавливает чтение остальных источников; причина записывается без секретов и текста сообщения.
4. При отсутствии любой обязательной переменной окружения API-запрос не выполняется; остальные источники продолжают работать.
5. Вызовы ограничены перечислением чатов и чтением истории; нет запросов на отправку/прочтение сообщений или настройку push.
6. Новые материалы идут по существующему пути обработки модели; промпт и критерии важности этим изменением не меняются.
7. Для источника API корректно хранится тип `api`; миграция схемы совместима с уже созданными источниками и кандидатами источников.
8. README, Kanban и SPEC описывают переменные, ограничения доступа и новый источник.
9. Модульные тесты покрывают нормализацию ответа, выбор чатов, дедупликацию, отсутствие ключей, авторизационный отказ и безопасность журналирования.

## Не входит

- Подключение API Wildberries или Яндекс Маркета.
- Получение либо передача секретов через чат, изменение переменных окружения Coolify, push или production-развёртывание.
- Настройка Ozon Push API или webhook.
- Запрос истории покупателей, статусов заказов и других не относящихся к новостям чатов.
- Изменение промпта, модели, важности находок, карточек влияния на склад и уведомлений.
