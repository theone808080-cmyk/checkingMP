# Правила проекта

Радар собирает публичные новости маркетплейсов и формирует черновые ИИ-находки для проверки владельцем. Перед работой сверяй назначение и команды в [README.md](README.md), а текущее состояние и следующий шаг — в последней записи [progress.md](progress.md).

- Изменяй поведение только по задаче из `SPEC.md` после явного утверждения владельцем.
- Одна задача SPEC — один коммит; в сообщении коммита указывай номер задачи.
- До коммита запускай полный набор тестов: `python -m unittest discover -s tests -q` с отдельной тестовой PostgreSQL через `TEST_DATABASE_URL`.
- Если реализация отступает от SPEC, сообщи владельцу до коммита.
- Не добавляй в Git ключи, токены, пароли, `.env`, данные ручной проверки или дампы баз.
- Черновые сигналы модели требуют проверки человеком и не являются юридическим заключением.
- Для разработки используй отдельную ветку и рабочую копию в `.worktrees/`; не считай незапушенную ветку интегрированной или развёрнутой.
- Сохраняй содержательные вехи в `progress.md`; инвентарь файлов и методика принадлежат `README.md`.
- В `work/` могут находиться локальные материалы и тестовая база; проверь содержимое и активные процессы до любого перемещения или очистки.
