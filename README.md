# Радар соответствия маркетплейсов

Пилот собирает публичные обновления Ozon, Wildberries, Яндекс Маркета и «Честного знака» по бытовой химии. Материалы сохраняются в PostgreSQL, а серверная команда `cycle` последовательно запускает сбор и обработку ограниченной партии через OpenRouter. Результаты модели остаются черновиками, требующими проверки человеком.

Схема работы: публичные источники → сборщик → PostgreSQL → обработка OpenRouter → очередь ручной проверки → веб-интерфейс. В Telegram Mini App доступны исходные публикации и отдельная лента ИИ-находок с пятью уровнями важности, автоматической сортировкой, фильтрами и ссылками на первоисточники.

Задачи 1–10 объединены и отправлены в `main` форка `theone808080-cmyk/checkingMP`. Коммит `a2cd409` успешно развёрнут в Coolify 2026-11-11: образ собран, проверка `/health` прошла. Полный набор из 193 тестов дал 190 успешных результатов; 3 Docker smoke-теста пропущены локально, поскольку Docker CLI отсутствует. Расписания резервного копирования и поиска новых источников ещё не настроены.

Задача 11 реализована в ветке `feat/task-11-openrouter-diagnostics`: отказ обработки ответа OpenRouter теперь записывает безопасную категорию и этап в stderr, не включая запрос, материалы, ответ или секреты; модельное поле сериализуется так, чтобы Unicode-разделители не нарушали формат одной строки. ## Настройки

Скопируйте `.env.example` в локальный `.env` только для локальной работы. Задайте `DATABASE_URL` с подключением к PostgreSQL, а при включённом веб-доступе — `WEB_BASIC_USER` и `WEB_BASIC_PASSWORD`. Не добавляйте секреты в Git.

Для обработки используются `OPENROUTER_API_KEY`, `OPENROUTER_MODEL`, `OPENROUTER_BASE_URL`, `OPENROUTER_TIMEOUT`, `OPENROUTER_BATCH_SIZE` и `OPENROUTER_MAX_TOKENS`. Модель по умолчанию — `openai/gpt-4.1-nano`; размер партии — 10, тайм-аут — 120 секунд, предел генерации — 2500 токенов. Базовый адрес — `https://openrouter.ai/api/v1`. API-ключ читает серверный процесс из переменной окружения. Пользователь вводит реальный `OPENROUTER_API_KEY` только в настройках окружения Coolify во время развёртывания; ключ не помещается в `.env.example`, Git или отчёты.

Для личного Telegram Mini App и уведомлений используются `TELEGRAM_TOKEN`, `TELEGRAM_CHAT_ID` и `RADAR_MINIAPP_URL`. Первые две переменные нужны для проверки подписи Telegram и идентификатора владельца; все три — для уведомлений и настройки кнопки меню. `TELEGRAM_CHAT_ID` должен быть числовым идентификатором личного чата владельца, а `RADAR_MINIAPP_URL` — HTTPS-адресом страницы `/miniapp`. Значения вводятся владельцем непосредственно в окружение Coolify и не публикуются в Git, переписке или снимках экрана. Если какая-либо из трёх переменных уведомлений отсутствует, сбор и обработка продолжаются без рассылки.

Резервное копирование использует `BACKUP_ENCRYPTION_KEY`, `BACKUP_DIR=/backups` и `BACKUP_RETENTION_COUNT=14`. Ключ должен быть Base64URL-кодировкой случайных 32 байт; задайте его только в защищённых настройках Coolify. Образы включают клиент PostgreSQL 17: `pg_dump` не может создавать копию с сервера более новой основной версии, чем сам клиент ([документация PostgreSQL 17](https://www.postgresql.org/docs/17/app-pgdump.html)).

Ранее пользователь указал адрес радара `https://raqlihvwgqgaqkd5a1eflm4k.201-34-144-213.sslip.io/`. Перед настройкой следует сверить его с актуальным публичным HTTPS-адресом приложения в Coolify и указать в `RADAR_MINIAPP_URL` этот адрес с путём `/miniapp`. Указанный ранее адрес сам по себе не подтверждает, что новая версия уже развёрнута.

Обычная страница радара `/` защищена логином и паролем из `WEB_BASIC_USER` и `WEB_BASIC_PASSWORD`. Внутри Telegram открывается `/miniapp`: сервер проверяет подписанные Telegram данные и разрешает доступ только указанному владельцу. Пустая оболочка Mini App доступна до входа, но материалы и статусы источников выдаются только после успешной проверки Telegram либо Basic Auth. Лента показывает исходные материалы, фильтры периода и площадки; в разделе «Как собрано» находятся статусы источников и схема работы.

В защищённой странице радара ссылка «путь обработки» открывает read-only JSON API `/api/findings/{id}/trace` с цепочкой находки, первоисточника, материала, запусков и этапов. Трассировка доступна только по Basic Auth; Telegram Mini App её не открывает. В записях сохраняются статусы, время и безопасные коды ошибок, без полных текстов материалов и запросов к модели. Повторные попытки добавляются отдельно и сохраняют предыдущую историю.

## Развёртывание в Coolify

1. Создайте PostgreSQL в Coolify и скопируйте предоставленную строку подключения `DATABASE_URL` для приложения.
2. Создайте приложение из Git-репозитория и выберите сборку по `Dockerfile`. Веб-сервис использует команду контейнера по умолчанию `python main.py web`.
3. В разделе переменных окружения приложения задайте `DATABASE_URL`, `WEB_BASIC_USER`, `WEB_BASIC_PASSWORD`, `OPENROUTER_MODEL=openai/gpt-4.1-nano`, `OPENROUTER_BASE_URL=https://openrouter.ai/api/v1`, `OPENROUTER_TIMEOUT=120`, `OPENROUTER_BATCH_SIZE=10` и `OPENROUTER_MAX_TOKENS=2500`. Установите `OPENROUTER_API_KEY` там же непосредственно в Coolify. Не записывайте его в репозиторий или эту документацию.
4. Создайте в Coolify Scheduled Task для приложения с командой `python main.py cycle` и расписанием Cron `0 6,18 * * *`.

Cron запускает цикл дважды в день — в 06:00 и 18:00 по часовому поясу сервера, на котором выполняется Scheduled Task. Перед включением расписания проверьте часовой пояс сервера в настройках Coolify или самого сервера и настройте его согласно желаемому местному времени. Только если сервер настроен на UTC, это расписание соответствует 09:00 и 21:00 по Москве на даты пилота. Время фактического старта может немного отличаться из-за очереди задач. Цикл сначала собирает новые материалы и затем обрабатывает одну ограниченную партию напрямую через PostgreSQL и OpenRouter. Отдельный worker API или перенос данных обработки через веб-сервис не используется.

При первом запуске полностью настроенной рассылки цикл до сбора фиксирует уже имеющиеся материалы как историю: они не отправляются задним числом. После сбора личное уведомление «Новых новостей: N» с кнопкой «Открыть ленту» создаётся только для новых материалов. Подтверждённые отправки учитываются в базе. Если Telegram принял сообщение, но ответ потерялся в сети, при повторной попытке возможен дубликат. При ошибке первой фиксации истории настроенный цикл откладывает сбор до следующей попытки, чтобы не потерять уведомление.

### Резервные копии PostgreSQL

Создайте постоянный том Coolify для копий на том же VPS и подключите его к приложению и его Scheduled Tasks по пути `/backups`. Он должен быть отдельным от тома данных PostgreSQL. Локальный файл `.backup` зашифрован AES-256-GCM и дополнительно проверяется SHA-256; ключ не хранится в самом томе. Бесплатный вариант на том же VPS не защищает от потери VPS или диска.

В окружении приложения задайте `BACKUP_ENCRYPTION_KEY` и `BACKUP_DIR=/backups`. Роль `DATABASE_URL` должна иметь право подключаться к рабочей базе и создавать временную базу для проверки восстановления. Создайте отдельные задачи Coolify: `python main.py backup` ежедневно (например, `0 3 * * *`) и `python main.py verify-backup` ежемесячно (например, `0 4 1 * *`). Расписание выполняется в часовом поясе сервера. Команда проверки восстанавливает копию только в новую базу с префиксом `radar_backup_verify_` и удаляет только созданную ею базу.

Страница радара показывает дату, размер последней успешной копии и результат последней проверки восстановления. Сторож сообщает о неуспешной или просроченной копии, ошибке восстановления и пропуске ежемесячной проверки. Владелец должен сверить подключение постоянного тома и защищённую переменную ключа до включения расписания; расписание этой ветки пока не активировано.

### Поиск и проверка новых источников

Поиск запускается отдельно от обычного цикла сбора командой `python main.py discover-sources`. Для недельного запуска создайте отдельную Coolify Scheduled Task с этой командой; пример расписания — `0 8 * * 1` (каждый понедельник в 08:00 по часовому поясу сервера). Поиск только создаёт очередь кандидатов и не подключает их к сбору.

Google News RSS работает без ключа Exa. Если используется `EXA_API_KEY`, задайте его только в защищённых переменных Coolify и заранее выключите платный перерасход в аккаунте Exa. Exa запускается в режиме Lite с ограниченным числом результатов; при исчерпании кредита он приостанавливается до начала следующего месяца по UTC, а Google News продолжает работать.

Владелец проверяет очередь на `/sources/review` в обычном браузере под Basic Auth: просмотр примеров, настройка типа и области, безопасная проба и ручное одобрение либо отклонение. Telegram-сессия не может изменять очередь. Одобренный источник начинает участвовать в последующем сборе; сам факт обнаружения этого не делает.

После настройки трёх Telegram-переменных оператор может отдельно запустить в контейнере приложения `python main.py telegram-set-menu`. Команда изменяет кнопку меню существующего бота для указанного личного чата и задаёт ей открытие Mini App. Она не запускается автоматически при развёртывании или сборе.

На текущем этапе реализация подготовлена в рабочей ветке: развёртывание этой версии, отправка реального уведомления и изменение меню бота ещё не подтверждены. При активации необходимо проверить фактическое состояние базы и адрес приложения, затем под наблюдением владельца проверить получение одного уведомления, кнопку и открытие ленты, переходы к первоисточникам, фильтры и обе темы. Также следует проверить обычный вход в радар и выполнение задачи по расписанию. Существующая AI-рассылка Finder рассматривается отдельно: её источник и расписание нужно сначала точно установить.

Установите месячный лимит расходов `$5` в настройках аккаунта OpenRouter до включения расписания. Это настраивается в аккаунте OpenRouter, а не переменной окружения приложения. Контролируйте остаток лимита и выполнение задач в панели провайдера и Coolify.

## Сторож работоспособности

Задача 4 запускается отдельным приложением Coolify из этого же репозитория и `Dockerfile`. В качестве команды укажите `python main.py watchdog`, установите `WATCHDOG_MODE=1` и подключите постоянный том `/data` для файла резервного состояния и отметки последней проверки. Docker healthcheck проверяет свежесть отметки сторожа; для основного веб-приложения он обращается к локальному `/health`.

В отдельное приложение сторожа добавьте `WATCHDOG_DATABASE_URL`, `RADAR_HEALTH_URL` с адресом радара и путём `/health`, `COOLIFY_API_URL`, `COOLIFY_APPLICATION_UUID`, `COOLIFY_API_TOKEN`, `TELEGRAM_TOKEN` и `TELEGRAM_CHAT_ID`. Все значения задаются только в Coolify. `WATCHDOG_DATABASE_URL` должен принадлежать отдельной роли PostgreSQL: разрешите ей чтение таблицы `cycles` и чтение/запись только таблицы `watchdog_incidents`. Таблицы создаёт основное приложение при запуске. Для таблиц в схеме `public` права выдаются администратором PostgreSQL:

```sql
GRANT USAGE ON SCHEMA public TO radar_watchdog;
GRANT SELECT ON TABLE cycles, backup_runs TO radar_watchdog;
GRANT SELECT, INSERT, UPDATE ON TABLE watchdog_incidents TO radar_watchdog;
```

Для Coolify создайте отдельный токен с правом `deploy`, ограниченный приложением радара. Такое право позволяет перезапускать, останавливать и развёртывать выбранное приложение; не выдавайте этому токену права `root` или `write`. Токен не помещайте в Git и не используйте для других приложений.

Сторож проверяет состояние раз в пять минут. После трёх последовательных ошибок доступности веб-приложения он один раз запрашивает перезапуск, только если база доступна; повторный сбор новостей не запускается. Он сообщает в Telegram об отсутствии успешного полного цикла более 14 часов, повторных ошибках источника или обработки ИИ в двух циклах, недоставке уведомления и неудачном восстановлении. Повторные сообщения объединяются, восстановление отмечается отдельно. Ноль новых новостей не считается сбоем. Если недоступны сам Coolify, VPS, сеть сервера или Telegram, внутренний сторож не сможет отправить оповещение.
## Локальный запуск и ручная проверка

Нужны Python 3.12+ и PostgreSQL. Создайте виртуальное окружение и установите зависимости:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Задайте переменные из `.env` в окружении текущего терминала и запустите цикл:

```powershell
.\.venv\Scripts\python.exe main.py cycle
```

Для проверки релевантности владелец может выгрузить слепую выборку, вручную заполнить `label` одним из пяти классов, импортировать файл и посмотреть отчёт:

```powershell
.\.venv\Scripts\python.exe main.py prepare-judge-review
# Заполнить label в work\judge-review.json классами:
# practical_change, seller_action_or_risk, industry_context, irrelevant, uncertain
.\.venv\Scripts\python.exe main.py import-judge-labels work\judge-review.json
.\.venv\Scripts\python.exe main.py judge-report
```

Файл выборки не содержит оценок и совпавших правил; он хранится в игнорируемой папке `work/`. Команда `process` автоматически сохраняет локальные оценки новых материалов перед основным вызовом модели, но эти оценки не меняют очередь и результаты. При изменении словарей в `config/relevance-rules.json` увеличивайте поле `version`, чтобы новая оценка сохранилась рядом с предыдущей.

Для ручной проверки ИИ-находок можно подготовить выгрузку ожидающих материалов и импортировать проверенный JSON:

```powershell
.\.venv\Scripts\python.exe main.py prepare-review
.\.venv\Scripts\python.exe main.py import-review work\reviewed-signals.json
```

Пример структуры для импорта находится в `config/reviewed-signals.example.json`. Человек проверяет сигналы до импорта; неподтверждённые выводы модели не считаются юридическим заключением.

Для полного набора тестов задайте `TEST_DATABASE_URL` с отдельной тестовой PostgreSQL и запустите:

```powershell
./.venv/Scripts/python.exe -m unittest discover -s tests -q
```

Тестовую базу не направляйте на рабочую БД.

Запустить веб-интерфейс отдельно можно командой `python main.py web`. Веб-страницы требуют `WEB_BASIC_USER` и `WEB_BASIC_PASSWORD`; `/health` доступен для проверки состояния базы данных. `python main.py health` локально проверяет PostgreSQL и доступность OpenRouter, но не запускает обработку.

## Границы пилота

Система читает только публичные источники. Она не входит в кабинеты, не обходит защиту сайтов и не выполняет действия на маркетплейсах. Если ни один источник не удалось прочитать или активных источников нет, сбор завершается ошибкой и цикл останавливается до обработки. Если хотя бы один источник прочитан, цикл продолжается; ошибки остальных источников фиксируются. Ошибка модели или невалидный ответ не импортируются автоматически. Повторный запуск после неопределённого сбоя следует выполнять только после проверки состояния очереди.
