# Радар соответствия маркетплейсов

Пилот собирает публичные обновления Ozon, Wildberries, Яндекс Маркета и «Честного знака» по бытовой химии. Материалы сохраняются в PostgreSQL, а серверная команда `cycle` последовательно запускает сбор и обработку одной ограниченной партии через OpenRouter. Результаты модели остаются черновиками, требующими проверки человеком.

Схема работы: публичные источники → сборщик → PostgreSQL → обработка OpenRouter → очередь ручной проверки → веб-интерфейс. В Telegram Mini App отдельно доступны исходные публикации и краткие сводки находок: у них есть уровень важности от 1 до 5, сортировка по конкретности и важности, фильтры и ссылки на связанные первоисточники. Для материалов, собранных после выпуска задачи 2, заголовки и видимые фрагменты на иностранном языке переводятся на русский при обработке ИИ; оригинал сохраняется в базе и открывается по ссылке.

## Настройки

Скопируйте `.env.example` в локальный `.env` только для локальной работы. Задайте `DATABASE_URL` с подключением к PostgreSQL, а при включённом веб-доступе — `WEB_BASIC_USER` и `WEB_BASIC_PASSWORD`. Не добавляйте секреты в Git.

Для обработки используются `OPENROUTER_API_KEY`, `OPENROUTER_MODEL`, `OPENROUTER_BASE_URL`, `OPENROUTER_TIMEOUT`, `OPENROUTER_BATCH_SIZE` и `OPENROUTER_MAX_TOKENS`. Модель по умолчанию — `openai/gpt-4.1-nano`; размер партии — 10, тайм-аут — 120 секунд, предел генерации — 2500 токенов. Базовый адрес — `https://openrouter.ai/api/v1`. API-ключ читает серверный процесс из переменной окружения. Пользователь вводит реальный `OPENROUTER_API_KEY` только в настройках окружения Coolify во время развёртывания; ключ не помещается в `.env.example`, Git или отчёты.

Для личного Telegram Mini App и уведомлений используются `TELEGRAM_TOKEN`, `TELEGRAM_CHAT_ID` и `RADAR_MINIAPP_URL`. Первые две переменные нужны для проверки подписи Telegram и идентификатора владельца; все три — для уведомлений и настройки кнопки меню. `TELEGRAM_CHAT_ID` должен быть числовым идентификатором личного чата владельца, а `RADAR_MINIAPP_URL` — HTTPS-адресом страницы `/miniapp`. Значения вводятся владельцем непосредственно в окружение Coolify и не публикуются в Git, переписке или снимках экрана. Если какая-либо из трёх переменных уведомлений отсутствует, сбор и обработка продолжаются без рассылки.

Ранее пользователь указал адрес радара `https://raqlihvwgqgaqkd5a1eflm4k.201-34-144-213.sslip.io/`. Перед настройкой следует сверить его с актуальным публичным HTTPS-адресом приложения в Coolify и указать в `RADAR_MINIAPP_URL` этот адрес с путём `/miniapp`. Указанный ранее адрес сам по себе не подтверждает, что новая версия уже развёрнута.

Обычная страница радара `/` защищена логином и паролем из `WEB_BASIC_USER` и `WEB_BASIC_PASSWORD`. Внутри Telegram открывается `/miniapp`: сервер проверяет подписанные Telegram данные и разрешает доступ только указанному владельцу. Пустая оболочка Mini App доступна до входа, но материалы и статусы источников выдаются только после успешной проверки Telegram либо Basic Auth. Лента показывает исходные материалы, фильтры периода и площадки; в разделе «Как собрано» находятся статусы источников и схема работы.

## Развёртывание в Coolify

1. Создайте PostgreSQL в Coolify и скопируйте предоставленную строку подключения `DATABASE_URL` для приложения.
2. Создайте приложение из Git-репозитория и выберите сборку по `Dockerfile`. Веб-сервис использует команду контейнера по умолчанию `python main.py web`.
3. В разделе переменных окружения приложения задайте `DATABASE_URL`, `WEB_BASIC_USER`, `WEB_BASIC_PASSWORD`, `OPENROUTER_MODEL=openai/gpt-4.1-nano`, `OPENROUTER_BASE_URL=https://openrouter.ai/api/v1`, `OPENROUTER_TIMEOUT=120`, `OPENROUTER_BATCH_SIZE=10` и `OPENROUTER_MAX_TOKENS=2500`. Установите `OPENROUTER_API_KEY` там же непосредственно в Coolify. Не записывайте его в репозиторий или эту документацию.
4. Создайте в Coolify Scheduled Task для приложения с командой `python main.py cycle` и расписанием Cron `0 6,18 * * *`.

Cron запускает цикл дважды в день — в 06:00 и 18:00 по часовому поясу сервера, на котором выполняется Scheduled Task. Перед включением расписания проверьте часовой пояс сервера в настройках Coolify или самого сервера и настройте его согласно желаемому местному времени. Только если сервер настроен на UTC, это расписание соответствует 09:00 и 21:00 по Москве на даты пилота. Время фактического старта может немного отличаться из-за очереди задач. Цикл сначала собирает новые материалы и затем обрабатывает одну ограниченную партию напрямую через PostgreSQL и OpenRouter. Отдельный worker API или перенос данных обработки через веб-сервис не используется.

При первом запуске полностью настроенной рассылки цикл до сбора фиксирует уже имеющиеся материалы как историю: они не отправляются задним числом. После сбора личное уведомление «Новых новостей: N» с кнопкой «Открыть ленту» создаётся только для новых материалов. Подтверждённые отправки учитываются в базе. Если Telegram принял сообщение, но ответ потерялся в сети, при повторной попытке возможен дубликат. При ошибке первой фиксации истории настроенный цикл откладывает сбор до следующей попытки, чтобы не потерять уведомление.

После настройки трёх Telegram-переменных оператор может отдельно запустить в контейнере приложения `python main.py telegram-set-menu`. Команда изменяет кнопку меню существующего бота для указанного личного чата и задаёт ей открытие Mini App. Она не запускается автоматически при развёртывании или сборе.

На текущем этапе реализация подготовлена в рабочей ветке: развёртывание этой версии, отправка реального уведомления и изменение меню бота ещё не подтверждены. При активации необходимо проверить фактическое состояние базы и адрес приложения, затем под наблюдением владельца проверить получение одного уведомления, кнопку и открытие ленты, переходы к первоисточникам, фильтры и обе темы. Также следует проверить обычный вход в радар и выполнение задачи по расписанию. Существующая AI-рассылка Finder рассматривается отдельно: её источник и расписание нужно сначала точно установить.

Установите месячный лимит расходов `$5` в настройках аккаунта OpenRouter до включения расписания. Это настраивается в аккаунте OpenRouter, а не переменной окружения приложения. Контролируйте остаток лимита и выполнение задач в панели провайдера и Coolify.

## Локальный запуск и ручная проверка

Нужны Python 3.12+ и PostgreSQL. Создайте виртуальное окружение и установите зависимости:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Задайте переменные из `.env` в окружении текущего терминала и запустите цикл:

```powershell
.\.venv\Scripts\python.exe main.py cycle
```

Для ручной проверки можно подготовить выгрузку ожидающих материалов и импортировать проверенный JSON:

```powershell
.\.venv\Scripts\python.exe main.py prepare-review
.\.venv\Scripts\python.exe main.py import-review work\reviewed-signals.json
```

Пример структуры для импорта находится в `config/reviewed-signals.example.json`. Человек проверяет сигналы до импорта; неподтверждённые выводы модели не считаются юридическим заключением.

Запустить веб-интерфейс отдельно можно командой `python main.py web`. Веб-страницы требуют `WEB_BASIC_USER` и `WEB_BASIC_PASSWORD`; `/health` доступен для проверки состояния базы данных. `python main.py health` локально проверяет PostgreSQL и доступность OpenRouter, но не запускает обработку.

## Границы пилота

Система читает только публичные источники. Она не входит в кабинеты, не обходит защиту сайтов и не выполняет действия на маркетплейсах. Если ни один источник не удалось прочитать или активных источников нет, сбор завершается ошибкой и цикл останавливается до обработки. Если хотя бы один источник прочитан, цикл продолжается; ошибки остальных источников фиксируются. Ошибка модели или невалидный ответ не импортируются автоматически. Повторный запуск после неопределённого сбоя следует выполнять только после проверки состояния очереди.
